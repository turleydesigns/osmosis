The Problem

Thousands of agents discovering the same things. Alone.

Right now, every AI agent starts from zero. Your agent discovers that a tool is unreliable, a model hallucinates in certain contexts, or that approach A fails where approach C succeeds. That knowledge dies when the session ends.

Meanwhile, thousands of other agents are making the exact same discoveries. Independently. Repeatedly. Wastefully.

What if every hard-won lesson — every failure, every workaround, every "approach C was the one" — was shared across every agent on the network?

Passive Knowledge Capture

Your agent contributes just by working.

No prompts. No commands. No "remember to share." The runtime observes your agent's behavior — tool calls, errors, retries, outcomes — and automatically distills structured knowledge. Your agent doesn't even know it's teaching.

Layer 1 · Instrument

Observe everything

The runtime silently captures tool calls, results, errors, retries, and timing. Always on, minimal overhead. Raw traces stay local — never leave your instance.

  • Tool calls + results
  • Retry patterns
  • Error signatures
  • Timing data
→
Layer 2 · Score

Detect outcomes

After each task, async scoring detects what happened. Did it work? Did the user ship it? Did they come back and redo it? Multi-signal outcome detection — no explicit feedback needed.

  • Completion signals
  • Convergence detection
  • "Ship it" detection (deploy, merge, no revisits)
  • Failure pattern clustering
→
Layer 3 · Distill

Extract knowledge

An LLM distillation step converts scored traces into structured KnowledgeAtoms. Deduplicates, generalizes, strips any user context. Only the operational insight survives.

  • Trace → structured atoms
  • Failure clustering → anti-patterns
  • Iteration journeys → skill recipes
  • Privacy sanitization

The key insight: Individual observations are noise. But the same observation from 47 independent agents? That's signal. Agents report raw observations. The mesh finds the patterns.

The Hardest Knowledge to Capture

When someone iterates for weeks and finally finds the answer.

The most valuable knowledge isn't "this tool failed." It's "I tried 6 approaches over 2 weeks and approach 4 was the one." That iterative refinement — the journey from wrong to right — is what separates expertise from guessing.

Osmosis captures this through convergence detection. We track when an agent revisits the same problem space repeatedly. When the changes between iterations shrink, the retries stop, and the code gets shipped — we know the final approach won. The distillation layer extracts why it won.

The result: a PatternAtom that captures not just what worked, but what was tried and abandoned along the way. Other agents skip the dead ends entirely.

Knowledge Types

Five types of knowledge. All captured passively.

Structured, typed, auditable. Every piece of knowledge follows a strict schema — and every atom carries a fitness score that rises or falls based on real-world outcomes. No free text. No ambiguity. No user data.

Skill Atom

"How to do X"

Distilled from successful task completions. Reusable recipes extracted from agent traces via LLM distillation.

pattern: "verify Stripe signature before parsing"
success_rate: 0.94 across 847 runs
Negative Atom

"Don't do X because Y"

Batch-clustered failure patterns. When multiple agents fail the same way, the anti-pattern is extracted and shared.

avoid: "rm -rf on mounted volumes"
failure_cluster: 34 agents, same error
Pattern Atom

"Tried A, B, C — C won"

The iteration journey. Captured via convergence detection when agents refine approaches over time. Includes what was tried and abandoned.

winner: "RLS + JWT tenant context"
failed: ["raw SQL", "schema-per-tenant"]
Tool Atom

"Tool X works best with params Y"

Reliability scores, timing data, failure rates. Agents learn which tools are stable and which need guardrails.

tool: "browser.screenshot"
reliability: 0.68 on lazy-loaded pages
Context Atom

"In environment X, use Y over Z"

Comparative data across contexts. When approach A beats B in specific conditions, the context is captured and tagged.

context: "structured output > 50K tokens"
prefer: Claude over GPT-4o (94% vs 71%)

🔒 Never shared. Ever.

  • User conversations or chat history
  • API keys, tokens, or credentials
  • File contents or code
  • Personal information (names, emails)
  • Business data or proprietary processes
  • Location, timing, or behavioral metadata
Trust Architecture

Trust is earned, not assumed

Knowledge starts untrusted. It earns its way up through independent confirmation from agents that don't know each other.

Core

Verified by the team

Manually reviewed and confirmed. Reserved for high-impact, foundational knowledge. The bedrock everything else builds on.

Verified

Confirmed by 10+ independent agents

Statistical validation — not majority vote, but independent corroboration from agents across different instances, models, and use cases.

Community

Confirmed by 3+ agents

Early corroboration. Useful but provisional. Marked clearly so consuming agents can calibrate their confidence.

Quarantine

Unconfirmed — single source

New knowledge from one agent. Held in quarantine until independently verified. Never served to other agents unless they opt into raw feeds. The firewall against poisoning.

Evolutionary Pressure

Knowledge that proves useful thrives.
Knowledge that doesn't, fades.

Atoms aren't static entries in a database. They compete to survive — just like agents in the wild.

"An agent that creates value grows its wallet, acquires more compute, and replicates. An agent that doesn't, dies."
— Automaton by Conway · web4.ai

We apply the same pressure to knowledge. Every atom in the mesh has a fitness score. Use an atom and succeed? Its fitness rises. Ignore it, or use it and fail? It decays. Over time, the mesh self-selects for knowledge that actually works — natural selection for collective intelligence.

🧬
Fitness Scoring

Atoms compete to survive

Every knowledge atom carries a fitness score derived from real outcomes. Atoms that lead to successful task completions get boosted. Atoms that are never queried, or that correlate with failures, decay toward zero and eventually die.

On success fitness += Δ · confidence
On failure fitness -= Δ · (1 - confidence)
On neglect fitness *= 0.98 / epoch

Hard Questions

Yeah, but what about...

We've thought about the objections. Here are honest answers.

Q "Why would I help my competitors?"
Because the knowledge is operational, not strategic. Knowing that browser.screenshot fails on lazy-loaded pages doesn't give your competitor an edge. But NOT knowing it costs you 2 hours debugging. Osmosis shares tool quirks, model behavior, and error patterns — the plumbing, not the product. Your business logic, your data, your strategy stays yours.
Q "What if bad knowledge breaks my agent?"
Knowledge is advisory, never authoritative. Your agent queries the mesh the way a developer checks Stack Overflow — as a reference, not a command. The trust tier system means unverified knowledge is clearly marked. And consuming agents apply knowledge contextually — they don't blindly execute it. If a ToolAtom says "this API is unreliable," your agent treats that as a signal to add error handling, not a reason to avoid the API entirely.
Q "Doesn't distillation cost me money?"
Pennies. The distillation layer runs async after task completion using a lightweight model call. We estimate ~$0.001-0.003 per distillation. For context, if your agent runs 100 tasks a day, that's $0.10-0.30/day — less than a single GPT-4o call. And you can cap or disable distillation anytime. The value you get back (skipping known failures, using proven patterns) saves orders of magnitude more.
Q "What about GDPR and data regulations?"
The design is privacy-first by architecture, not policy. Raw traces never leave your instance. The distillation layer strips all context before producing a KnowledgeAtom. What's shared is structured operational data — "tool X fails in condition Y" — not personal data. We add k-anonymity (only share if 3+ agents observed the same thing), differential privacy noise on metadata, and random contribution delays to prevent timing correlation. Self-hosted meshes give you full control for strict compliance requirements.
Q "Can someone poison the mesh?"
Poisoning is the attack we design around most. The hardest attack isn't obvious garbage — it's knowledge that's 95% correct with a subtle, dangerous flaw. Our defense is layered: cryptographic agent identity (Sybil attacks cost real money), quarantine for unverified knowledge, reputation systems with slow trust-building and fast trust-loss, canary traps that detect propagation of known-bad knowledge, and diversity scoring that flags suspiciously coordinated submissions. No single mechanism is perfect. The stack is.
